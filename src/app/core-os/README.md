# Core OS

Reusable OS-style framework infrastructure belongs here.

This boundary is for shell, windowing, dock, tray, terminal, context menu, tooltip, notification, filesystem, and OS service code. Current route files may still lazy-load legacy component locations while the migration is staged.

## Current migration state

- `os.routes.ts`, the device guard, and the unsupported-device page define the current `core-os` route boundary.
- `app-registry/` owns application models and IDs, the default catalog and file associations, deterministic installed-handler resolution, instance creation, lifecycle/focus/minimize state, open-window persistence, and the `ApplicationManagerService` facade. Live consumers use the `@core-os/app-registry/*` package paths; every former game service/factory path re-exports the same class or symbol so Angular retains one root instance.
- `windowing/` owns the generic app-window lifecycle surface and reusable window header. Desktop and shared consumers use explicit `@core-os/windowing/*` leaf paths so public header use cannot traverse the heavier app-window/CLI dependency graph; the former template paths re-export the canonical component identities so selectors and downstream imports remain stable.
- `dock/` and `tray/` own the desktop launcher and menu-bar chrome. Desktop uses explicit canonical leaf paths, while the former system-component paths re-export the same standalone component identities. Feature services used by their controls remain compatibility dependencies until their own cohorts move.
- `context-menu/` owns the menu models, builder, injection token, CDK overlay service, external renderer template, and retained registry prototypes. Desktop uses the canonical service path, while every former game service/template/menu path re-exports the same constructor, component, token, or registry identity.
- `terminal/` currently owns only the renderer-agnostic typewriter queue, public event/types, timer lifecycle, mode state, and sound dispatch. CLI parsing, the terminal component/template, AI chat, sound, OS user, settings, and persistence remain staged legacy dependencies for later independent batches; the former typewriter path re-exports the same root service identity.
- `tooltip/` is the first reusable interaction package moved out of the legacy game tree. Live consumers import its standalone directive and types through `@core-os/tooltip`; the former directive, service, and overlay paths remain compatibility re-exports while downstream imports settle.
- `storage/` owns the IndexedDB-first OS key/value abstraction. Live consumers import `StorageService` through `@core-os/storage`; the former game-service path re-exports the same class so Angular retains one root service instance.
- `filesystem/` owns the versioned virtual filesystem, Finder application/window UI, and the filesystem-owned file-opening injection port. Desktop provides the application manager adapter so this package does not import the registry. Former component paths re-export the canonical identities; the former mock service path is a deprecated facade over canonical navigation/view state and retains its synchronous factory helpers. The app catalog, tray, and icon playground use the Core OS package directly.
- Most runtime implementation still lives under `src/app/components/game`; that location is legacy structure, not public-site ownership.
- Migration remains active roadmap work and must proceed in small import-only batches with route, persistence, lifecycle, keyboard, and rendered regression checks.
- Do not combine folder migration with a visual rewrite or delete compatibility paths without reference and archive review.
- The legacy OS login screen keeps Firebase authentication in place while presenting password-reset success and failure through inline accessible feedback. Success uses a polite status announcement without stealing focus; errors remain assertive, and duplicate reset requests are disabled while the current request is pending.

## Device capability gate

`guards/os-device.guard.ts` protects the interactive `/os` routes before authentication or desktop assets load. The guard requires a viewport of at least 1024 × 640 plus hover and fine-pointer support. Phones, touch-only tablets, and undersized windows redirect to the public `/os-device-required` explanation page.

### Component inventory

- `osDeviceGuard`: route-level capability check for `/os` and `/os/:app`.
- `OsDeviceRequiredComponent`: lightweight public fallback with routes back to the blog and homepage.
- `tooltip/TooltipDirective`: hover and keyboard-focus trigger that preserves existing `aria-describedby` values, assigns wrapper tooltips to the actual focused descendant, gives the nearest nested tooltip ownership while restoring a still-hovered ancestor, prioritizes a still-focused disclosure over unrelated pointer hover, persists while the trigger remains active, and supports Escape dismissal.
- `tooltip/TooltipService`: single-overlay lifecycle owner, including reentrancy-safe replacement callbacks, timer cancellation for programmatic callers, teardown, and viewport-relative positioning.
- `tooltip/TooltipOverlayComponent`: plain-text presentation boundary with tooltip semantics, size, position, arrow, fade, and class options.
- `storage/StorageService`: Observable key/value and collection API backed by the existing `AppStorage` / `keyvalue` IndexedDB contract with an availability-only localStorage fallback. IndexedDB mutations emit after transaction completion, persistence failures remain observable, and revision compare-and-set gives whole-snapshot clients an atomic stale-writer check. The localStorage strategy requires Web Locks for compare-and-set and otherwise fails closed.
- `filesystem/FileSystemService`: serialized, per-Firebase-UID, IndexedDB-backed version-1 virtual filesystem with stable entry IDs, deterministic compare-and-set seed import, UTF-8/storage and structural bounds, opaque revision conflict tokens, create/rename/move/duplicate, Trash/restore, tags, search, selection, sorting, and bounded session undo. Failed or stale writes do not commit in-memory state.
- `filesystem/FinderAppComponent`: macOS-inspired sidebar, per-window path history/selection/search/sort/dialog targets, list/grid/column listbox views, shared mutation refresh, roving keyboard selection, organization toolbar, keyboard shortcuts, focus-contained dialogs, Trash recovery, bounded diagnostic export/reset recovery, confirmed permanent deletion, and double-click/Enter metadata-preview dispatch with honest unsupported feedback. Folders in Trash remain inert until restored; actual byte opening and real-folder access remain separately gated phases.
- `filesystem/FINDER_FILE_OPENER`: narrow request/result injection port carrying stable virtual metadata plus an explicit content state. Desktop binds it to the application manager without creating a filesystem-to-registry runtime dependency.
- `filesystem/FinderWindowComponent`: lightweight view-projection boundary for the Finder list, grid, and column workspaces.
- `app-registry/ApplicationManagerService`: stable facade used by the desktop, dock, tray, app windows, Activity Monitor, and CLI to register, restore, launch, focus, close, and dispatch metadata-only file previews.
- `app-registry/ApplicationRegistryService` and `application-catalog`: canonical app lookup and the ordered catalog of preserved `APP_ID` entries. Installed file handlers resolve by exact MIME, MIME-family wildcard, extension, then legacy kind, with specific MIME mismatches failing closed and registration order breaking equal-score ties. The catalog temporarily imports concrete apps from the legacy game tree until feature-owned manifests are migrated separately.
- `app-registry/ApplicationLifecycleService` and `ApplicationFactory`: open-window instances, memory and instance limits, focus ordering, minimize/restore state, offsets, parameters, and base-app persistence. Minimized state is runtime-only so restored sessions cannot reopen invisible windows. Notification, media, and logging dependencies remain at compatibility boundaries until their own Core OS cohorts move.
- `app-registry/ApplicationStatePersistenceService`: narrow synchronous adapter for the exact localStorage key `applications`; it writes base app-ID arrays and continues accepting both string IDs and historical `{id}` records.
- `windowing/AppWindowComponent`: dynamic component host with explicit input handoff for parameter-aware OnPush apps, lifecycle-to-DOM focus transfer, descendant focus preservation, native buttons for close/minimize/zoom, Dock-targeted Genie-inspired animation, reduced-motion fallback, viewport-clamped pointer dragging, bounded resize/zoom, and document-listener/global-selection/animation teardown.
- `windowing/WindowHeaderComponent`: reusable title and window-control chrome used by Labs and the public not-found surface without importing the legacy game tree.
- `dock/DockComponent`: registry-driven desktop launcher for installed general applications, core Finder/Settings entries, transient running system applications, focus/restore, running indicators, launch bounce, account/role-gated destinations, notification testing, sign-out, and Trash. One click opens, focuses, or restores through the manager facade.
- `tray/SystemTrayComponent`: menu bar for application lifecycle, Finder view modes, memory display, sound, battery, clock, OS routes, authenticated logout, and user identity. Menu controls retain native button/link semantics and explicit ARIA state; failed logout remains visible in the open menu.
- `context-menu/ContextMenuService` and `ContextMenuBuilder`: one replaceable, pushed four-way CDK root overlay with invoker focus restoration plus recursive role filtering and complete parent/path metadata. Role filtering is presentation logic, not authorization.
- `context-menu/ContextMenuComponent`: recursive menu renderer with named menu/item/separator semantics, real roving focus, disabled/structural-row skipping, contained Home/End/Arrow navigation, submenu entry/return, viewport-fit nested placement, action/Escape/Tab dismissal, and focus-safe pointer/scroll branch closure.
- `terminal/TypewriterService`: mutable root queue for text output, line completion, active mode, sound state, prompt prefixes, timer cancellation, and lifecycle callbacks. Canonical consumers use the service/models leaf paths; compatibility coverage prevents a second queue or DI token.
- `LoginScreenComponent` (legacy location): shared public/OS authentication entry with accessible inline password-reset status and existing provider/email flows.

### Migration note

The guard is additive and leaves the legacy desktop, login, boot, sleep, and external route implementations in place. If the OS shell later gains a supported mobile layout, update the capability policy instead of duplicating or deleting the existing routes.

The tooltip migration changes package ownership without changing selectors or template inputs. It also removes HTML interpretation from tooltip copy, makes the service own its programmatic auto-dismiss timer, makes replacement callbacks reentrancy-safe, and gives focus users the same persistent disclosure and dismissal behavior as pointer users. Directive-owned tooltips remain visible until hover/focus ends or Escape dismisses them; the legacy `tooltipAutoDismiss` input remains accepted for template compatibility. Rollback is limited to restoring consumer imports and the three legacy implementations; routes, app IDs, persisted state, and Firebase behavior are unaffected.

The storage migration preserves the database, object store, raw keys, fallback selection, and existing public Observable signatures while hardening the contract: ordinary missing-value reads normalize to `null`, the recovery-only record read separately preserves key presence so a stored `null` cannot be mistaken for absence, IndexedDB mutations settle on transaction completion, storage failures reach subscribers, revision compare-and-set is atomic and presence-aware within one IndexedDB transaction, Task mutations serialize against the last successful snapshot, Patch Editor save/delete actions cannot overlap, and the localStorage fallback refuses origin-wide `clear()` calls. Atomic localStorage compare-and-set additionally requires Web Locks and fails visibly where unavailable. IndexedDB and JSON serialization are not equivalent, and an IndexedDB runtime failure does not silently switch data stores. Rollback requires restoring the implementation at the legacy path, the consumer imports, and the associated failure-handling changes; no data migration or Firebase change is required.

The app-registry migration is import-only. It preserves every `APP_ID` value, catalog order and entry, route, window constraint, memory and instance rule, focus/open/close behavior, root DI token, and the existing `applications` localStorage payload. Legacy imports are identity-tested against canonical constructors, and persisted object snapshots remain readable without rewriting browser data. Rollback restores the seven implementations to their former game service/factory paths and reverts live consumer imports; the compatibility exports can remain temporarily. No Firebase, content, route, or stored-data migration is required.

The windowing migration preserves the `app-window` and `app-window-header` selectors, inputs, dynamic component and parameter handoff, focus stream, close/collapse behavior, initial offsets, viewport clamping, resize limits, and styling. Pointer completion now reliably removes the transient resize class. Each active gesture owns a scoped document-selection lock that restores the prior inline style on completion or teardown; destroying an idle window cannot clear another subsystem's lock. Later activation parameters are forwarded to the existing embedded component without recreating it, allowing an already running Finder to honor the Dock Trash destination. Rollback restores the two component implementations and templates to their former paths and reverts three live consumer imports; routes, Firebase, app IDs, and stored state remain untouched. Extracting drag/resize behavior into a controller is deliberately deferred to a separately tested refactor.

The filesystem migration moves the service, Finder app, and Finder view boundary into `core-os/filesystem`. Former component imports retain constructor identity; the old mock-service path becomes a deprecated facade so synchronous factories remain available without making live Finder state nonpersistent. First use imports the retained asset tree into `core-os.virtual-file-system.user.<encoded Firebase UID>` within `AppStorage`; later loads preflight exact plain-object/JSON shape, dense arrays, field limits, and incremental serialized bytes before cloning and reusing version 1. Mutations serialize, compare revision tokens inside the storage transaction, and become visible only after persistence completes. Invalid or unknown stored data is preserved with bounded diagnostic-export/reset recovery; revision-bearing recovery compares its stored token, while the destructive confirmation may replace another revisionless corrupt value through the presence-aware revision-zero compare but cannot overwrite a newer valid nonzero revision. The warning tells users to close other Finder tabs. Unsupported binary, cyclic, or oversized fields are described or truncated and marked incomplete in the export. Permanent deletion remains user-confirmed. Rollback restores the legacy implementations and catalog/tray imports while leaving account-scoped values inert. The former origin-wide key is not migrated because its account owner cannot be proven. Finder does not delete host files, upload bytes, or change Firebase data, routes, content, or the existing `applications` key.

The Finder metadata-preview phase adds associations to existing catalog entries and binds the filesystem-owned opener port to `ApplicationManagerService` at the Desktop composition boundary. Exact and wildcard MIME matches outrank filename metadata; a specific MIME mismatch fails closed, while missing/generic MIME may fall back to extension and legacy kind. Finder sends metadata only. Music and Markdown Reader make that limitation visible and neither loads content inferred from the name or path. Preview parameters are runtime-only, so no filesystem schema, route, Firebase contract, storage key, or `applications` payload changes. Rollback removes the port binding, associations, and preview presentation while leaving existing virtual snapshots and app records compatible.

The dock/tray migration preserves the `app-dock` and `app-system-tray` selectors, standalone template dependencies, launcher click/double-click behavior, open/focus/close actions, role-gated account destinations, menu state, Finder view-mode bridge, memory formatting, sound/battery/clock controls, Sleep/Restart/Shutdown links, and existing styling. Both logout controls delegate session termination and successful redirect to `AuthService`; the dock no longer duplicates those outcomes through unconditional console warnings, and a failed tray logout stays in the open menu with an accessible error instead of falsely returning home with the Firebase session intact. The one-shot tray logout subscription deliberately survives tray teardown so the non-cancelable Firebase operation cannot lose the service's terminal redirect or failure logging. Legacy component paths are identity-tested against the canonical exports. Rollback restores both implementations/templates/specs to their former system paths and reverts the two desktop imports. Routes, Firebase configuration, app IDs, application persistence, filesystem state, and content are unchanged.

The context-menu ownership migration preserves `app-context-menu`, the builder and item/config shapes, generated IDs, role filtering, injection token, retained registry entries, desktop Open/Settings callbacks, pointer coordinates, replacement behavior, backdrop dismissal, and styling. Canonical and legacy exports are identity-tested so Angular still resolves one root overlay service and the same portal component. The separate hardening pass promotes the formerly unused external HTML placeholder into the canonical template, removes the no-op desktop Open With test entries, ignores bubbled desktop events, adds Context Menu/Shift+F10 opening, focuses and names the menu, recursively filters/annotates every submenu level, contains nested navigation keys, closes on action/Escape/Tab/scroll/navigation/teardown, restores the connected invoker, pushes the root through four CDK fallbacks, and flips/vertically fits nested panels at viewport edges. Rollback of ownership restores the four implementations and component spec to their former game paths and reverts the desktop import; rollback of hardening restores the prior inline renderer and pointer-only lifecycle. Routes, Firebase, app IDs, application persistence, user data, and content are unchanged.

The first terminal migration is ownership-only: `TypewriterService` and its public models move together, live producers/consumers use canonical leaf imports, and the former game-service path re-exports the exact constructor. Queue order, timer cadence, callbacks, prompt formatting, sounds, modes, output subjects, and `clear()` semantics remain unchanged and focused tests cover the OS-user and sound seams. The canonical service temporarily depends on legacy `SoundService` and `OsUserService`; their settings/storage dependencies do not move with it. CLI commands, the `[innerHTML]` renderer boundary, the terminal component, application catalog, routes, app IDs, window state, Firebase, and persisted data are unchanged. Rollback restores the implementation/spec to the legacy service path and reverts consumer imports; no data migration or deployment action is required.

The Dock/window behavior phase intentionally follows the completed ownership migrations. It replaces placeholder Dock icons with installed/running registry state, uses one-click activation, adds runtime-only minimize/restore and focus transfer, gives the yellow and green controls minimize and zoom behavior, and bounds animation through the matching Dock element with a reduced-motion fallback. The exact `applications` payload remains unchanged and contains no minimized flag. Rollback reverts the Dock/window templates and lifecycle methods without migrating browser data. Finder's virtual persistence and metadata-preview dispatch are now delivered; actual content opening and the optional user-selected local-folder adapter remain separate verified phases in `docs/ARCHITECTURE/CORE_OS_DESKTOP.md`.
